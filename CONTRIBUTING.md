# Contributing to @mrghozzi Open-Source Projects

First off, thank you for considering contributing! Projects in this ecosystem thrive because of developers, testers, and community members like you.

## Code of Conduct

By participating in any repository under the `@mrghozzi` umbrella, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md). Please treat everyone with respect and empathy.

---

## How Can I Contribute?

### 1. Reporting Bugs
- Before filing a bug report, check existing issues to ensure it hasn't already been reported.
- Use the **Bug Report** template when opening an issue.
- Clearly describe the issue, steps to reproduce, expected vs. actual behavior, and environment details (PHP version, OS, browser, etc.).

### 2. Suggesting Enhancements
- Enhancement suggestions and feature requests are always welcome!
- Use the **Feature Request** template.
- Explain the motivation behind the feature and how it benefits the project or users.

### 3. Submitting Pull Requests (PRs)
1. **Fork the repository** and create your branch from `main` or `master`:
   ```bash
   git checkout -b feature/my-cool-feature
   ```
2. **Follow Coding Standards**:
   - **PHP**: Adhere to PSR-12 coding style.
   - **Dart/Flutter**: Run `dart format .` and `flutter analyze`.
   - **JavaScript / CSS**: Keep clean, readable code and adhere to modern ES6+ standards.
   - **Lua**: Follow standard Lua/QBCore best practices and indentation.
3. **Commit Messages**:
   We recommend following [Conventional Commits](https://www.conventionalcommits.org/):
   - `feat: add indexnow retry queue`
   - `fix: correct token parsing in rest api`
   - `docs: update installation instructions`
4. **Push your changes and open a PR** against the `main` branch.
5. Provide a clear description in your PR using our PR template.
